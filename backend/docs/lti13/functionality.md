# LTI 1.3 Integration — Functionality Spec
**Feature:** LTI 1.3 (Learning Tools Interoperability v1.3) support for axis-ai
**Date:** May 2026 | **Author:** Ravi

---

## What This Feature Does

Allows any LMS that supports LTI 1.3 (Moodle, Canvas, Blackboard, etc.) to launch axis-ai
as an external tool with automatic SSO. Learners and teachers click a link inside their LMS
course — no separate login required. axis-ai recognises who they are, what role they have,
and (optionally) which learning space to show them.

---

## User Stories

### Admin (axis-ai side)
- As an axis-ai admin, I can register a Moodle instance as an LTI platform by entering 5 config
  values from Moodle, and axis-ai gives me 4 values to paste back into Moodle.
- As an axis-ai admin, I can see all registered LTI platforms, edit, enable/disable, or delete them.
- Each LTI platform is tied to exactly one axis-ai tenant (separate users, spaces, branding).

### Moodle Admin (customer side — no axis-ai plugin needed)
- As a Moodle site admin, I add axis-ai as an External Tool (LTI 1.3) using the 4 config values
  axis-ai gives me. This is a one-time setup per Moodle site.
- After setup, any teacher can add axis-ai as an activity in any course.

### Moodle Teacher
- As a Moodle teacher, I add an "External Tool" activity pointing to axis-ai.
- Optionally, I add a custom parameter: `space_slug=python-basics`
  so that learners from this course land directly on the Python Basics space.
- I can use a different slug in each course — Course A → python-basics, Course B → excel-advanced.
- If I don't add a custom parameter, learners land on their full axis-ai dashboard.
- My own account in axis-ai gets Creator role (I can manage spaces).

### Moodle Learner
- As a Moodle learner, I click the axis-ai activity link in my course.
- I am automatically logged in to axis-ai (SSO — no separate credentials).
- If the teacher set a `space_slug`, I land directly on that learning space.
- If no slug was set, I see my full dashboard.
- My account is auto-created on first launch (Just-in-Time provisioning).

## Role Mapping

| Moodle Role       | LTI 1.3 Role Claim                                      | axis-ai Role |
|-------------------|---------------------------------------------------------|--------------|
| editingteacher    | membership#Instructor                                    | creator      |
| teacher           | membership#Instructor                                    | creator      |
| student           | membership#Learner                                       | learner      |
| manager/admin     | institution/person#Administrator                        | admin        |
| (any unknown)     | (fallback)                                              | learner      |

## Space Slug

- Each axis-ai learning space has a `slug` field (e.g. `python-basics`, `excel-advanced`).
- Slugs are unique per tenant and URL-safe (lowercase, hyphens only).
- Creators and admins see and can edit the slug when creating/editing a space.
- A helper generates a slug from the space title automatically (editable).
- In Moodle custom parameters field: `space_slug=python-basics`
- axis-ai resolves slug → space, checks tenant match, redirects learner.
- If slug not found: falls back to /learn dashboard (no error shown).
- Multiple Moodle courses can each point to different slugs.

## Platform Registration Flow (One-Time, Per Moodle Site)

### Step 1 — axis-ai admin creates a platform record
The admin enters:
- Friendly name (e.g. "ACME University Moodle")
- Moodle issuer URL (e.g. `https://lms.acme.edu`)
- Client ID (from Moodle)
- Auth Login URL (from Moodle)
- Auth Token URL (from Moodle)
- JWKS / Key Set URL (from Moodle)
- Deployment ID(s) (from Moodle — can be multiple)
- Which tenant this platform maps to

axis-ai shows the admin the values to paste into Moodle:
- **Tool URL / Redirect URI**: `https://axisai.edzlms.com/lti/launch`
- **Initiate Login URL**: `https://axisai.edzlms.com/lti/login`
- **JWKS / Public Key Set URL**: `https://axisai.edzlms.com/.well-known/jwks.json`
- **Client ID**: (generated by Moodle — entered by admin)

### Step 2 — Moodle admin pastes values
Moodle site admin goes to: Plugins → Activity modules → External tool → Manage tools → Add
They fill in the 4 values above. Moodle then shows the Client ID and Platform details.

### Step 3 — Done
Teachers can now add "External Tool → axis-ai" to any course.

## Launch Flow (Every Learner Click)

1. Learner clicks axis-ai link in Moodle course
2. Moodle sends OIDC login request → `GET /lti/login`
3. axis-ai stores state+nonce in Redis (60s TTL), redirects back to Moodle auth
4. Moodle signs a JWT (id_token) with all claims, POSTs to `POST /lti/launch`
5. axis-ai validates:
   - Signature (via Moodle's JWKS — cached in Redis 1h)
   - Nonce (one-time, deleted after use)
   - Expiry, issuer, audience
6. axis-ai extracts: user email/name, LTI role, course info, custom params
7. axis-ai JIT-provisions user (create if new, update name if changed)
8. axis-ai issues a one-time token (OTT, 30s TTL) stored in Redis
9. Backend redirects to `https://axis.edzlms.com/lti/complete?ott=<token>&to=/learn/python-basics`
10. Next.js `/lti/complete` page exchanges OTT for axis JWT cookies, redirects learner

## What Is NOT Needed

- No Moodle plugin (PHP) — uses Moodle's built-in External Tool module
- No changes to Moodle database
- No custom Moodle code whatsoever
- No Moodle admin needs to touch server config

---

## Security Considerations

- Nonces are one-time-use (deleted from Redis immediately after validation)
- State parameter prevents CSRF on the OIDC callback
- OTT (one-time token) for cookie handoff is 30s TTL, deleted after first use
- JWKS keys from Moodle are cached (1h) but re-fetched on validation failure
- RSA-2048 key pair stored as PEM in axis-ai .env; public key exposed via JWKS endpoint
- LTI users cannot reset password via email flow (they use LTI for auth)
